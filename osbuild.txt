* Updating the OpenWRT OS
  - shipped in mid-2021 with TinaLinux
  - look for SOC in OpenWRT Table of Hardware
    * https://openwrt.org/toh/start
    * https://d1.docs.aw-ol.com/en/study/study_1tina/
      - Tina Linux is an embedded software system for intelligent hardware products developed by Allwinner Technology based on the Linux kernel. Tina Linux is based on the OpenWrt-14.07 version of the software development kit, which contains the kernel source code, drivers, tools, system middleware, and application packages used in Linux system development.
      - The Linux Kernel of the Tina platform uses Linux3.4, Linux3.10, Linux4.4, Linux4.9, Linux5.4, and other kernels.
      -- The baidu SmartSpeaker uses a Linux4.9 kernel
  - OpenWrt Wiki
    * https://oldwiki.archive.openwrt.org/doc/howto/buildroot.exigence
    * 14.07 branch (Barrier Breaker)
      - git clone -b barrier_breaker git://github.com/openwrt/archive.git
  - backup current firmware and configuration
    * dd if=/dev/nand0 of=/tmp/backup_firmware.bin
      - 93,614,080 Bytes (93.6MB)
  - mount unused rootfs
    * mkdir /tmp/mnt
    * mount -r -t squashfs /dev/nand0p7 /tmp/mnt  # mount B, use nand0p5 to mount A
    * mount -r -t squashfs /dev/by-name/rootfs{A,B} /tmp/mnt  # better way to identify which to use
    * to update rootfs:
      - put the new rootfs into the mounted (unused) partition: e.g., /tmp/mnt/sysupgrade
      - copy new kernel image into the partition: e.g., /tmp/mnt/sysupgrade/vmlinuz
      - extract backup to mounted partition to preserve settings
    * update u-boot environement to boot from the new partition
      - fw_setenv boot_partition <new_partition>
      - fw_setenv bootcmd 'run boot_<new_partition>'
      --> start with existing env and modify the necessary bits

    * ./scripts/feeds update -a
    * ./scripts/feeds install -a

  - configure the kernel
    * make menuconfig
    * select Target System (e.g., Allwinner (sunxi))
    * choose Subtarget and Board

  - build
    * make -j${nproc}
  - flash the firmware
    * sudo dd if=path/to/openwrt.img of=/dev/sdX bs=1M

* get device tree out of the device
  - 'dtc -I fs -O dts /proc/device-tree > extracted.dts'
    * 'dtc' doesn't exist on the stock device
  - all nodes/properties in /proc/device-tree
    * /proc/device-tree is a symlink to /sys/firmware/devicetree/base
    * use /proc/device-tree as recommended by kernel documentation
  - copy /proc/device-tree
    * on <host>
      - 'adb pull -a /proc/device-tree <dstPath>'
      - 'dtc -I fs -O dts <dstPath> > device-tree.dts'

* Tina Linux OTA
  - https://cloud.tencent.com/developer/article/2225252
  - components
    * Boot0
      - main function is to initialize the dram and load the run uboot
      - generally do not need to be modified
    * Uboot
      - full of features, supports burning writing, starting kernel, burning key and some other customized functions
    * sys_config
      - for platforms that use linxu3.4/uboot2011, sys_config is spliced with uboot after packaging
      - for platforms that use linux3.10/uboot2014 and later, sys_config merges with the configuration of the device tree during the packaging phase to generate the final dtb
      - Linux 5.4 is no longer integrated into dtb.
    * DTB
      - the device tree is aggregated by the dts configuration and the sys_config configuration
    * u-boot.fex
      - final uboot for the platform using linxu3.4/uboot2011 is actually uboot+sys_config
    * boot_package.fex
      - uboot that is used in the platform using linux3.10/uboot2014 and later
        * contains files determined by the configuration file boot_package.cfg
      - generally at least contains uboot and dtb
      - security scheme will contain some security-required file files
      - may also have bootlogo and other files
    * toc0.fex
      - Boot0 is used in the security scheme
    * toc1.fex
      - uboot used by the security scheme is similar to the boot_package.fex description
        * which actually contains multiple files such as dts
